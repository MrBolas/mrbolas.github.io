# Spec: CV page on mrbolas.github.io

Status: draft — awaiting approval
Date: 2026-10-29
Repo: `MrBolas/mrbolas.github.io` (branch `master`, GitHub Pages from root)

## Problem

`index.html` is a 139-line single page with About / Featured Projects / Tech Stack. It
reads like a summary, not a CV: no work history, no education, no contact route, no
linked projects, no shareable preview. A recruiter landing on it has nowhere to go and
learns nothing verifiable.

## Goal

`index.html` becomes a one-page CV that a recruiter can skim in 30 seconds and share
with a colleague. Still one static file, still zero build step.

## Non-goals

- No framework, bundler, or JS dependency. Stays a hand-edited HTML file.
- No blog, dark mode, i18n, analytics, or CMS.
- No invented content. Every fact is supplied by João or drawn from a real repo.

## Content model

Order is deliberate: identity → summary → evidence → contact.

1. **Header** — full name, target role, location, one-line contact strip.
2. **Summary** — 2–3 sentences. Replaces the current "About Me".
3. **Experience** — company, title, dates, 2–4 outcome bullets each. Reverse
   chronological. This is the substance of the page.
4. **Tech stack** — grouped by area, not a comma dump.
5. **Education** — degree, institution, years, thesis.
6. **Languages** — Portuguese C2, English C1, Spanish B1.
7. **Contact** — email, LinkedIn, GitHub, site footer.

**No featured-projects section for now.** The old one listed `agent-toolkit`, which is a
private repo. Rather than ship an empty or unverifiable section, leave an HTML comment in
`index.html` marking where a projects section goes, and fill it when there are repos worth
showing. The experience bullets carry the evidence meanwhile.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| PDF export | Print stylesheet (`@media print`), not a committed `resume.pdf` | A committed PDF is a second copy that drifts silently. Print-to-PDF is always current. |
| Featured projects | None for now; comment-marked slot in the HTML | The only candidate repo is private. An empty section is worse than no section. |
| Phone number | Omitted | Public pages get scraped; email and LinkedIn are sufficient routes. |
| Social preview | One committed `og-image.png` (1200×630), regenerated in monochrome | Matches the page; a purple card for a grey page would look broken. |
| Email exposure | `mailto:` link with the address rendered from reversed characters via CSS-free markup alternative deferred to implementation | Full address in plain HTML is harvestable; exact technique is an implementation detail, not a spec constraint. |
| Styling | Monochrome document: white page, near-black ink, hairline rules, small-caps section labels | Revised 2026-10-29 — a page described as a CV should read as a document, not a landing page. No colour, no cards, no shadows. |
| CSS location | Stays inline until the file passes ~300 lines, then extract to `styles.css` | Avoids churn now, names the trigger for splitting. |

## Requirements

**Structure and semantics**

- R1 — Single `<main>` with `<header>`, `<section>` per content block, each with an `h2`.
- R2 — An `<h1>` containing the name (currently "MrBolas 👨‍💻" — use the real name).
- R3 — Emoji in headings removed; they read as noise to screen readers.

**Contact**

- R4 — Email and LinkedIn links present in the header *and* footer.
- R5 — GitHub link points to `https://github.com/MrBolas`.
- R6 — All links have discernible text; no bare "here" or icon-only links.

**Shareability**

- R7 — `<meta name="description">` present, 120–160 chars.
- R8 — Open Graph: `og:title`, `og:description`, `og:image`, `og:url`, `og:type=profile`.
- R9 — Twitter card `summary_large_image` pointing at the same image.
- R10 — `<link rel="canonical" href="https://mrbolas.github.io/">`.

**Print**

- R11 — `@media print` prints black on white, with no decoration carried over.
- R12 — External links print their URL in parentheses after the text.
- R13 — No section splits across a page break; no orphaned headings.

**Quality**

- R14 — Text contrast ≥ 4.5:1 for body copy, including muted secondary text.
- R15 — Keyboard focus is visible on every link.
- R16 — Renders usably at 320px wide without horizontal scroll.
- R17 — No external network requests beyond the optional OG image (no Google Fonts, no CDN).
